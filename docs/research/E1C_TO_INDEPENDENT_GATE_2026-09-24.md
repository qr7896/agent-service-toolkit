## 当前停止判断

任务无关公开失败定位器已能给30/30提供窗口，v1明确路径16/30，v2静态测试 import 增至20/30；窗口存在不代表文件正确。v4.3 对剩余19题的57次普通 Flash 调用0净新；v4.4–v4.7 的受限推理、安全路径回显、受控 ACI 与公开测试 import 定位小样本均无直接新增；v5.0 加公开新增测试断言的3题6次调用也0新增。因此**不再按这些已试过的提示/定位方式向未解题增加付费调用**。v4.8–v4.9 通过公开验证错误的通用缺导入修复，零模型新增两条 DEV 解（跨版本 best-of13/30），说明候选后处理有有限收益，但不构成单次30题成功率。这是基于冻结小样本停止规则的成本控制，而不是声称其他任务不可解。

## 下一版必须改变的机制

1. 先用零模型规则给出文件候选、失败测试/traceback provenance、短源码窗口和 abstain 原因；不要把“30/30有窗口”当作定位正确率。可借鉴 [SWE-agent ACI](https://github.com/SWE-agent/SWE-agent/blob/main/docs/background/aci.md) 的简洁全目录搜索、约100行文件查看与编辑后 lint，以及 [Agentless SWE-bench 流程](https://github.com/OpenAutoCoder/Agentless/blob/main/README_swebench.md) 的文件→代码元素→编辑位置三级定位、候选验证。这是设计参考，尚未实现/验证在本项目有收益。
2. v4.6 已验证**受控交互式检索→精确编辑**原型：搜索后自动展示原 base 短窗口，被拒编辑提供安全源码窗口，每题≤3请求；3题0新通过，不应原样扩批。下一步把候选后处理的可结构化错误（如未导入标准库模块）纳入候选校验/修复，并限定自动修复类型及回归预算；不得用模糊编辑替代精确来源验证。
   v5.0 的公开新增测试断言三题6调用仍0新解，故也不应直接扩批。零模型 coverage 探针显示 Sphinx9230 现有前三窗口均偏离目标执行路径，`docfields.py` 则确有132行执行；但原/新增测试的生产增量行接近0，下一版只可把执行覆盖用作候选过滤/校验，不能把它等同于故障真值。
3. 新机制先用现有30题中预定的小样本做零调用回归和受限付费 canary；只有出现新的 official resolved、且无安全/预算异常，才冻结完整30题 run identity。历史 best-of 可以作诊断，但宣称“30/30开发题全通过”必须来自**同一冻结版本、同一完整30题运行**，不能拼接多版本。

## 全新任务 one-shot 门槛

- 在看任何新任务的题面、测试结果或模型输出之前，冻结软件 SHA、模型与提示、定位/编辑/验证协议、调用/输出/整批预算和无自动重试规则。
- 从固定 SWE-bench task-tree commit 采用确定性排序，排除现有 E1-C 30题、所有已 materialize/admission/DEV 的任务，以及 E1-B sealed TEST；先仅做零模型 source identity、Base-Fail、Gold-Pass 与镜像 digest 准入。不能根据新任务的题意或失败结果挑选有利样本。
- 固定样本量、替补顺序、环境失败处理与资源计划后，一次性运行；不在新批次逐题调参，不复用它为开发集后仍称其独立。分别报告 attempted/admitted/resolved、模型请求与已知/未知 token、预算/网络/验证失败。
- 当前新批次**尚未选择/准入/付费运行**。本机镜像占用和磁盘余量可能限制30题准入；需先确认资源，不能因 11/30 DEV 或单测通过擅自宣称入门槛已过。
